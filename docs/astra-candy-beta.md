# Astra 门票糖果题（Beta）

完整续接探针通过，只能说明当时的门票协议检查通过。糖果题是额外的质量样本，不能保证后续请求都保持相同质量。

糖果题有两个用途：

1. **借出门槛**：开启 Cookie 路由池后自动生效，不受下面的观测开关控制。
2. **使用后观测**：在「自动打票策略」中启用「启用糖果测试验证使用后的票据」后生效，默认关闭。

两者共用同一份结果：同一张票（账号、模型、门票和路由 Cookie 都相同）在任一途径测过，另一途径不再重复测。

## 借出门槛

打票全流程里，来源账号和非来源账号都打自己的票，不用借来的票当种子。`gpt-6-astra` 和 `gpt-5.6-sol` 的票通过糖果题之后，才能在有效期内按同一个模型套到其他非来源账号的业务请求上：带上这张票的 state 和路由 Cookie，出口用借票账号自己的配置。只套已通过糖果题的票：

- 优先套来源账号的票；
- 来源账号没有可套的票时，套其他账号自己打到的票（含后台打票和单号定向打票）；
- 借来的票不会再转借，账号也不会套自己刚借来的票。

同一账号的主票和备用票都可借给其他账号的业务请求，优先借剩余时间更长的。其他账号的票需要已加载到当前进程（后台打票轮次会读取），未加载的暂不参与借出。借来的票不进入打票流程。

- 门票入库后自动测一次 Beta 糖果，用这张票自己的账号、state、路由 Cookie 和出口。通过后，有效期内所有其他非来源账号的业务请求都可以套用它。答错则这张票到期前不会被套用。网络失败等无法判断的结果 1 分钟后在下一轮打票时重试，不再重复入库。
- 通过的票在到期前一直可借。答错、门票重签、路由变化、响应模型不符视为未通过，这张票到期前不再借出，也不再重测。
- 网络失败、超时、账号凭证失效等无法判断的情况，1 分钟后再测。
- 同一张票同时只测一次；测试中的票最长占位 50 秒。
- 结果只保存在当前进程，最多 2048 条；重启后借出前会重新测。
- 业务请求不等待糖果题，也不为了套票再发探针。没有已通过的票时，请求按该账号自己的票或原配置转发。
- 测试结果写入「打票全流程 → 号池调度」流程事件，标注 Beta。快速复用面板的来源行会显示「等待糖果题测试」或「未通过糖果题，不会借出」。
- 每次业务请求成功借到票，「打票全流程 → 门票入库」都记一条「业务请求借票 · 业务请求借自 #ID 账号名（模型），网关 chat.gateway.unified-N.api.openai.com」。网关地址只取自路由 Cookie 里声明的 OpenAI 主机名，不记录 Cookie 本身。服务日志同时记 `openai_codex_ticket injected`（含借票账号、出借账号、模型和网关名，不含票据或 Cookie）。
- 打票请求只要响应 Cookie 里带了网关主机名，无论这次有没有打到票，「打票全流程 → 探针校验」都记一条「发现网关」。网关 host 历史库同时记一笔来源观察。页面保留最近 200 条流程事件。

## 使用后观测

已入库、通过探针的 SSE Astra 门票被真实 HTTP 请求使用后，在上游返回 HTTP 200、业务响应关闭并释放出口占用时，后台尝试发送一发糖果题。没有业务请求时不主动测。该观测使用对应账号、门票、路由 Cookie 和已记录出口，发送独立题目，不复制业务对话。

保存策略时省略该字段保留原值；关闭后不再发送新的观测请求，已经发出的请求在原期限内完成。

观测结果展示在「打票全流程 → 号池调度」和流程事件中，标注 Beta。答错、网络失败、超时、门票重签、路由变化和响应模型不符分别记录。原有号池加入/移出统计不包含这些事件。

观测结果只影响这张票能否借出，不修改门票、账号、模型映射、冷却、分组或调度开关，不触发业务重试。业务请求不等待观测结果，观测中的上游错误也不返回给用户。

## 开销和边界

- 适用于 `gpt-6-astra` 和 `gpt-5.6-sol` 的已验证 780 门票、SSE 传输。其他票形、WebSocket 和手动探针不自动触发。
- 借出门槛每张新候选票最多多一发上游请求；使用后观测每张票最多一发。换票会产生新样本；重启后会重新测，去重不是持久化保证。
- 使用后观测最多同时运行 2 个，满载直接跳过，后续业务请求可以再次尝试。没有后台排队。
- 业务流结束时票已过期就不测；等待出口期间过期、账号身份改变或采票关闭，记录跳过原因。
- 每次额外请求可能消耗账号额度，不进入用户请求用量和计费记录。总期限 45 秒，单次模型调用沿用已有探针超时。
- 额外请求仍消耗网络、上游和出口资源；并发限制并不代表零资源开销。
- 只保存固定结果码和账号/模型/时间等流程元数据，不保存糖果输出、票据、Cookie 或认证头。
- 糖果题通过不代表当前门票有效、号池状态正常或手工质量测试通过。页面组件截图使用虚构数据，未验证生产上游质量。

回滚代码即可停止新增测试，无数据库迁移；旧版可能隐藏新增的流程事件类型。
